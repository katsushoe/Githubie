# ADR 0005: Local Streamable HTTP MCP server exposing 15 typed tools

- Status: Accepted

## Context

Githubie must expose GitHub operations to MCP clients (Claude Code, Codex) running on the same machine, without becoming a general-purpose network service and without hand-rolling the MCP protocol.

## Decision

Use the official `ModelContextProtocol.AspNetCore` package (v2.2.0) hosted in an ASP.NET Core minimal app (`WebApplication.CreateSlimBuilder`). Kestrel binds only `127.0.0.1:<mcp_port>` (default `45460`, distinct from Buckettie's `45450`). `AddMcpServer().WithHttpTransport(transport => transport.Stateless = true).WithTools<GithubieMcpTools>(...)` registers exactly 15 typed tools plus `get_version`, defined as instance methods on `GithubieMcpTools` decorated with `[McpServerTool(...)]` and constructor-injected gateways. An `app.Use` middleware validates the `Origin` header (`McpOriginValidator`) before routing to the MCP endpoint.

## Alternatives

- Hand-rolled JSON-RPC endpoint: rejected because it duplicates protocol behavior the official SDK already implements correctly (including Streamable HTTP's dual `application/json` + `text/event-stream` Accept negotiation, discovered the hard way during real-machine verification).
- stdio transport only: rejected because Githubie is designed to run as a persistent Windows Service shared across multiple client sessions, not spawned per-client.
- External network binding: rejected per Security principle (loopback-only trust boundary).

## Impact

Tool schemas are generated by reflection over method signatures (`Microsoft.Extensions.AI.AIFunctionFactory`), not hand-written JSON Schema. This requires the passed `JsonSerializerOptions` to have an explicit `TypeInfoResolver`; omitting it throws at first tool invocation, not at build time (see ADR 0011 for the related parameter-naming decision this reflection-based generation also drives).

## Security conditions

- Loopback-only Kestrel binding; no reverse proxy is supported by this design.
- Origin header validation rejects non-loopback or mismatched-port Origins while still allowing clients that omit the header entirely.

## Operational conditions

Server startup fails fast (non-zero exit, error to stderr) if `githubie.json` is invalid or the platform is not Windows, rather than starting in a degraded state.

## Implementation, tests, and documentation

`Githubie.Server.Program`, `GithubieMcpTools`, `GithubieMcpJson`, `McpOriginValidator`. Verified live on real Windows hardware: server startup, `initialize`, `tools/list` (all 15+1 tools with correct schemas), `tools/call` success and error paths, all via real curl HTTP requests during Phase 1 real-machine verification.
